一、项目定位与目标

开发一套面向专升本备考人群的智能刷题系统。核心目标是"快速诊断薄弱点 + 精准查漏补缺"：通过 AI 算法实现个性化题目推荐，让学生把有限复习时间集中在最薄弱的知识点上。

系统采用次第迭代的学习机制：学生刷完题目后，系统更新其知识点掌握情况，生成学习报告，再据此推送下一轮练习，形成"做题 → 诊断 → 再练习"的闭环。

项目按阶段推进，先做网页版，网页版稳定后再做小程序版；每完成一个阶段发放相应补助，根据实际进度提供支持。开发流程坚持"先文档、后开发"——本文档即为此环节产物。

二、用户分层与核心刷题路径

系统面向两类用户，需分别设计刷题路径：

用户类型核心诉求刷题路径
学习型用户从头系统学习，尚未进入复习状态按课程知识点树状结构逐章推进，章节末设综合测试，据此判断薄弱点并决定下一章进度
模拟测试型用户考前冲刺、查漏补缺直接作答完整综合试卷进行摸底，结束后生成诊断报告指出薄弱知识点，供针对性补漏

两条路径最终汇合到同一套题集与作答逻辑，区别只在"入口"和"组卷方式"：学习型按知识点顺序抽题，模拟测试型按考纲分数比例随机组卷。

三、团队分工与开发模式

  • 团队共 6 名同学，按三大模块各分 2 人自由组队协作。
  • 小唐负责把控进度、分配任务，并在开发前整理本开发文档发群供讨论确认。
  • 后端统一使用 Python。相比 Java 虽然效率略逊，但代码简单、上手快、外部服务（尤其 AI 接口）生态成熟。

三大核心任务模块：

  1. 题库设计与数据准备（建库、题型定义、知识点标记、题库扩充）；
  2. 前端树状刷题界面（知识树、题集、作答、诊断，本人负责部分）；
  3. AI 接口与题目解析（对接大模型、生成并比对解析）。

四、数据库设计（双核结构）

数据库是项目基础，采用"一静一动"双核设计。

4.1 题库信息表（静态内核）

作为后台不动的基础库，存储：题干、选项、答案、关联知识点、题目解析。

  • 题型：【待确认】原始材料存在分歧——会议纪要写"单选题、多选题、填空题"三种；设计概要写"选择题和填空题"两类客观题。本方案暂按三种（单选/多选/填空）设计，理由是覆盖会议口径且均为客观题、便于 AI 判卷与即时反馈。此点须团队尽快确认，因为它直接影响选项组件与判分逻辑。
  • 确保所有题目具备明确的标准答案，便于系统自动判分与学生即时查看。
  • 题目按知识点字段归类。现有题目的知识点字段先空出，由负责人利用思维导图统一标记。
  • 需购买专升本计算机专业三年制考纲及复习资料，用于扩充当前可能过时的题库。

4.2 用户状态表（动态）

记录：用户个人信息、当前学习进度、历史答题对错、知识点掌握度统计。该表是 AI 精准推荐与下次练习推送的数据依据。

五、前端界面设计

5.1 设计基准：知识树

前端的核心难点是"课程 → 知识点 → 题目"多层级树状结构，需支持折叠展开以提升美观度。老师提供的示意图为横向思维导图样式：根节点在左、曲线向右展开、带描边的圆角节点、主题/副主题分层。前端据此设计为三级树：

  • 第一级：课程（根，如"专升本计算机基础"）；
  • 第二级：章节（如"数据结构与算法"）；
  • 第三级：知识点（叶子，如"栈与队列"），其下挂载题集链接。

节点上直接呈现做题进度条与掌握状态，颜色语义统一为：绿色=已掌握，红色=薄弱，灰色=未开始。这样把"每个节点显示进度条"与"红绿标记薄弱/已掌握知识点"两项需求合并到一个组件中。

5.2 页面清单与交互链路

前端第一阶段聚焦以下页面，登录、个人信息、做题记录等界面暂不开发：

  1. 知识地图（首页）：三级知识树，可折叠展开、全部展开/收起；点击叶子知识点进入对应题集。
  2. 题集列表页：展示某知识点下的题目、题型分布、完成度进度条与重置按钮；题目按"已答对/答错/作答中/未做"标记状态。
  3. 单题作答页：支持单选、多选、填空三种题型；选项点击或文本输入 → 提交 → 后台判错 → 查看解析 → 重置。解析区展示由 AI 双模型比对生成的题目解析。
  4. 诊断报告页（模拟测试后）：以红绿标记薄弱与已掌握知识点及正确率，提供"去练习"入口直达薄弱知识点题集，实现"诊断 → 补漏"闭环。

主交互链路：点击知识点 → 题集列表 → 点击单题作答 → 提交判错 → 查看解析/重置。

5.3 视觉风格

采用暖灰纸底、青绿主色、朱红警示色的设计语言，衬线体大标题搭配无衬线正文，刻意避开蓝紫渐变、毛玻璃等通用化后台模板观感，突出"学习工具"的克制气质。移动优先、兼顾后续小程序适配。

六、题库接口与抽题规则

  • 按知识点提取：依据知识点树状结构，按知识点逐个抽题形成题集页面。
  • 按比例随机组卷：依据考纲要求的分数比例，从数据库随机抽题生成模拟卷。
  • 标准答案：所有题目须有明确答案，支持自动判分与即时查看。
  • 题目不足时的补充：当题库题目用完，可通过 AI 生成新题补充；若用户对 AI 答案有异议，后续安排专人提供人工服务。

七、AI 接口与题目解析

  • 对接 DeepSeek 与豆包两个大模型的 Prompt 接口：提交题目，获取正确答案与解析。
  • 针对原题库"有答案无解析"的问题，通过双模型交叉验证完善解析——例如两模型均选 A 才采纳；并把两份答案解析做比较，是否一致，以此提升答案与解析的可靠性。
  • 无需自研 AI 算法。前端只负责把接口返回的 analysis 字段展示出来。

八、前后端接口数据约定（建议）

为避免联调扯皮，建议先把以下 JSON 结构定死，后端按此返回、前端按此渲染：

  1. 知识树：{ id, name, parent_id, progress, status }，其中 status 取 mastered / weak / learning / untouched。
  2. 题集条目：{ id, stem, type, status }，type 取 single / multiple / blank。
  3. 单题详情：{ id, stem, type, options: [{key, text}], answer, analysis }；填空题 options 为空，answer 可为字符串或多选数组。
  4. 提交判分：请求 { questionId, userAnswer }，返回 { correct, analysis }。

接口就绪前，前端以本地 mock 数据开发，视图层无需改动即可切换真实接口。

十、待确认事项与风险

  1. 题型数量（重要）：三种（单选/多选/填空）还是两类（选择/填空）？影响选项组件与判分逻辑，须优先确认。
  2. 知识点标记分工：现有题目知识点字段空出后，由谁用思维导图统一标记？需明确负责人与时间。
  3. 考纲资料采购：专升本三年制计算机考纲及复习资料由小唐采购（待办中写明"明天去闲鱼购买"），到货后据此更新题库与组卷比例。
  4. 会议纪要工具：待办中提到"使用元宝 App 自动开启纪要记录""整理确认腾讯会议自带纪要功能"，属会务事项，与开发并行。
  5. 前端范围：登录、个人信息、做题记录按会议要求暂缓，若后续需要须另行排期。
