本文档只讲前端两件事：一是前端怎么设计（技术选型、页面结构、组件拆分、状态与样式），二是前端怎么和后端对接（接口清单、数据格式、调用时序、mock 切换、联调与异常处理）。业务背景与整体分工见《智能刷题系统设计与开发文档》。文中凡标注"【待确认】"处需与后端或团队约定后确定。

一、前端职责与范围

1.1 做什么

前端负责"树状刷题界面"这一整块，具体包括四个页面：

  1. 知识地图（首页）：三级知识树，可折叠展开，节点带进度条与掌握状态；
  2. 题集列表页：某知识点下的题目列表，含完成度、作答状态、重置；
  3. 单题作答页：单选/多选/填空三种题型的作答、提交判分、查看解析；
  4. 诊断报告页：模拟测试后以红绿标记薄弱与已掌握知识点，可一键跳到薄弱题集。

1.2 暂不做什么

按会议要求，登录、个人信息、做题记录三类界面第一阶段不开发。这意味着前端第一阶段不需要处理用户身份与鉴权，所有接口默认面向单个当前用户；若后端接口要求 token，需另行确认。【待确认】

1.3 前端在系统中的位置

数据流是单向的：后端返回 JSON → 前端存到本地状态 → 渲染界面；用户操作 → 前端组装请求 → 调后端接口 → 更新本地状态 → 界面刷新。前端不做判分、不做 AI 解析、不直接读数据库，只负责展示与交互，判分与解析结果都来自后端。

二、技术选型与工程结构

2.1 选型

层面选型理由
框架Vue 3（组合式 API）递归组件天然适合渲染无限层级知识树；改数据界面自动更新，省去大量手动 DOM 操作；国内资料多，上手快
构建Vite启动快、配置少，npm run dev 即可开发
路由Vue Router（hash 模式）四个页面跳转；hash 模式避免静态部署刷新 404
HTTPfetch 或 axios调后端接口；原生 fetch 零依赖，axios 拦截更方便，二选一
样式原生 CSS + CSS 变量不引 UI 组件库，避免通用后台观感，配色 token 集中管理

2.2 目录结构

src/
├─ api/                 接口层：每个接口一个函数，集中管理 URL 与请求
│  ├─ request.js        统一封装 fetch（baseURL、错误、loading）
│  └─ knowledge.js      知识树/题集/题目/判分/诊断接口
├─ views/               页面组件（4 个）
│  ├─ KnowledgeMap.vue / QuestionSet.vue
│  ├─ QuestionDetail.vue / Diagnostic.vue
├─ components/          复用组件（3 个核心）
│  ├─ TreeNode.vue      递归树节点
│  ├─ ProgressBar.vue   进度条
│  └─ QuestionCard.vue  单题卡片（按题型切换控件）
├─ router/index.js      路由表
├─ mock/data.js         模拟数据（接口就绪前的假数据）
├─ styles/global.css    全局样式与设计 token
└─ main.js

分层原则：页面只管布局与业务流程，接口调用集中在 api/，视图里不出现裸 URL。这样后端改地址时只改一处。

三、页面设计与路由

3.1 路由表

路径页面说明
/KnowledgeMap知识地图首页
/set/:idQuestionSet题集列表，:id 为题集 id
/question/:setId/:qidQuestionDetail单题作答，带题集 id 与题目 id 便于返回
/diagnosticDiagnostic诊断报告

3.2 页面间流转

首页点知识点 → 题集列表 → 点某题 → 作答页 → 提交看到解析 → 下一题；题集列表可返回首页；诊断页可从首页进入，点"去练习"跳到薄弱知识点题集。

3.3 各页面关键设计点

知识地图：递归渲染三级树；节点显示名称、进度条、掌握状态色；章节可折叠，叶子可点击进题集；提供"全部展开/收起"。默认展开前两级，避免一上来信息过密。

题集列表：顶部显示完成度进度条与重置按钮；每题一行，标记状态（已答对/答错/作答中/未做）与题型徽章。

单题作答：核心是 QuestionCard 按 type 切换控件——单选渲染圆形选项、多选渲染方框选项、填空渲染输入框；提交后显示正误与解析区，解析区带"AI 双模型比对一致"标识。

诊断报告：分薄弱/已掌握两栏，各知识点显示正确率进度条；薄弱项提供"去练习"按钮跳对应题集。

四、核心组件设计

4.1 TreeNode（递归树节点）

整个前端技术含量最高的组件。思路是组件在自己模板里调用自己：一个节点渲染自身（名称、进度条、状态点），若有子节点则递归渲染 TreeNode。折叠/展开用一个布尔状态控制子节点容器是否渲染。

关键 props：node（当前节点数据）、isRoot（是否根）、expandCtrl（父级下发的展开/收起指令）。点击行为：有子节点则切换展开；叶子则跳转到对应题集。三级连线用 CSS 边框 + 圆角实现，无需引图表库。

4.2 ProgressBar（进度条）

props：value（0-100）、status（mastered/weak/learning/untouched）、showLabel。颜色随 status 变化：绿=掌握、红=薄弱、深绿=学习中、灰=未开始。宽度用 transition 做平滑动画。

4.3 QuestionCard（单题卡片）

按题型切换的核心组件。内部维护：选中项 selected（单选/多选）、输入值 blankInput（填空）、是否已提交 submitted。

判分逻辑（前端先做本地判断，最终以后端返回为准）：

  • 单选：选中项等于答案；
  • 多选：选中项集合与答案集合排序后完全一致；
  • 填空：输入与答案忽略大小写后相等。

提交后高亮正确答案与错误选择，展示解析。切换题目时重置所有状态。

五、状态管理

第一阶段页面少、状态简单，用组件本地状态（Vue 的 ref/reactive）即可，暂不引入 Pinia。各状态归属：

状态存放位置来源
知识树数据KnowledgeMap接口 GET 知识树
展开/收起TreeNode 本地用户点击
题集列表、完成度QuestionSet接口 GET 题集
当前题目、选中答案、是否提交QuestionCard 本地接口 GET 题目 + 用户输入
判分结果、解析QuestionCard接口 POST 判分返回
诊断数据Diagnostic接口 GET 诊断

原则：能从后端拿的不放死在前端；用户操作产生的临时状态放组件本地。

六、样式与设计 token

全局 CSS 变量集中定义：暖灰纸底 #f7f6f2、青绿主色 #0f6e56、朱红警示 #d85a30、近黑文字 #2c2c2a；衬线体大标题 + 无衬线正文。红绿语义严格对应会议要求（红=薄弱，绿=掌握）。注意：这是网页 UI 配色；导出到 Word 的文档则遵循全黑文字规则，两者场景不同，不冲突。

七、与后端对接（重点）

7.1 对接总原则

  1. 契约先行：后端按约定格式返回，前端按约定格式渲染；字段一旦定下，双方都不要单方面改。
  2. 集中管理：所有 URL 写在 api/ 一处，配一个 baseURL；后端地址变化只改一处。
  3. mock 先行：接口没就绪时读本地 mock，视图代码不变；接口就绪后把数据源从 mock 换成接口函数即可。
  4. 前端不做判分：提交答案后判分结果、正确答案、解析全部由后端返回，前端只负责显示。

7.2 接口清单（建议，需与后端确认）

编号用途方法路径调用时机
A1获取知识树GET/api/knowledge-tree进入首页
A2获取题集列表GET/api/sets/{setId}进入题集页
A3获取单题详情GET/api/questions/{questionId}进入作答页 / 切题
A4提交判分POST/api/answers/submit点"提交答案"
A5重置题集进度POST/api/sets/{setId}/reset点"重置"
A6获取诊断报告GET/api/diagnostic进入诊断页
A7按考纲组卷POST/api/papers/generate阶段二模拟测试

路径前缀、是否带版本（如 /api/v1）、鉴权方式均【待确认】。

7.3 数据格式约定

A1 知识树响应：返回整棵树，节点结构如下。

{
  "id": "ch2", "name": "数据结构与算法", "parentId": "c1",
  "level": 2,              // 1课程 2章节 3知识点
  "progress": 38,          // 0-100
  "status": "learning",    // mastered/weak/learning/untouched
  "setId": null,           // 叶子节点挂题集 id
  "children": [ ... ]      // 子节点，递归
}

A2 题集列表响应：

{
  "setId": "s6", "knowledgeName": "栈与队列",
  "counts": { "single": 8, "multiple": 2, "blank": 2 },
  "done": 4, "total": 12,
  "questions": [
    { "id": "q1", "stem": "栈的特点是（ ）。", "type": "single", "status": "correct" }
  ]
}

A3 单题详情响应：

{
  "id": "q1", "type": "single",       // single/multiple/blank
  "stem": "栈的特点是（ ）。",
  "options": [                        // 填空题此项为空数组
    { "key": "A", "text": "先进先出" },
    { "key": "B", "text": "先进后出" }
  ],
  "answer": "B"   // 单选字符串；多选数组如 ["A","B"]；填空字符串
}

注意：作答前是否下发 answer【待确认】。若不下发，前端提交后只显示后端返回的正误与解析，不显示"正确答案"高亮；若下发，前端可本地高亮。建议作答阶段不下发，避免答案暴露在前端。

A4 提交判分请求/响应：

请求：{ "questionId": "q1", "setId": "s6", "userAnswer": "B" }
       （多选 userAnswer 为数组，填空为字符串）
响应：{
  "correct": true, "correctAnswer": "B",
  "analysis": "栈是先进后出的线性表……"
}

A6 诊断报告响应：

{
  "score": 68, "total": 100, "duration": 42,
  "weakPoints":    [ { "id": "k6", "name": "栈与队列", "accuracy": 35, "setId": "s6" } ],
  "masteredPoints":[ { "id": "k1", "name": "计算机发展", "accuracy": 92 } ]
}

诊断项直接带 setId，前端"去练习"按钮可直接跳转，无需再映射。【待确认】

7.4 调用时序（一个完整作答流程）

  1. 进首页 → 调 A1 拿知识树 → 渲染；
  2. 点知识点 → 路由跳题集页 → 调 A2 拿题集 → 渲染列表与完成度；
  3. 点某题 → 作答页 → 调 A3 拿题目 → 渲染控件；
  4. 用户作答 → 点提交 → 调 A4 → 拿到 correct/analysis → 高亮并显示解析；
  5. 点下一题 → 用新题目 id 重复第 3 步（组件内部重置状态）；
  6. 点重置 → 调 A5 → 刷新题集进度。

7.5 mock 到真实接口的切换

第一阶段用 mock/data.js 提供假数据，函数签名与接口函数保持一致（如 getKnowledgeTree()、getQuestionSet(id)）。切换方式：把视图里 import 的来源从 mock/data 改为 api/knowledge，其余代码不动。建议加一个开关变量 USE_MOCK，方便随时切换演示。

7.6 异常处理与边界

  • 加载态：每个页面首次请求显示"加载中"，避免白屏。
  • 失败重试：请求失败显示错误提示 + 重试按钮，不静默失败。
  • 空状态：题集为空、诊断无数据时显示友好提示，而非空白。
  • 并发与防抖：提交按钮在请求返回前置灰，防重复提交。
  • 数据兜底：后端字段缺失时给默认值（如 progress 缺失按 0），避免渲染报错。
  • 题型扩展：若题型从三种增加，QuestionCard 需新增控件分支——这也是题型必须尽早定死的原因。

八、与后端的联调流程

  1. 定契约：双方确认第七章的接口路径与字段，冻结 mock 数据结构；
  2. 并行开发：前端用 mock 跑通界面，后端实现接口，互不阻塞；
  3. 接口联调：后端给测试地址，前端关掉 mock 逐个接口替换，用浏览器开发者工具检查请求/响应；
  4. 走查主链路：按 7.4 时序完整走一遍"首页→题集→作答→判分→诊断"；
  5. 问题反馈：字段不符、状态不对统一记录，后端修接口或前端调适配层。

九、阶段实施计划

阶段前端交付依赖
阶段一四页面 + 三组件，用 mock 跑通主链路无（可独立开发）
阶段二接真实接口，替换 mock，打通判分与进度回写后端 A1-A5 就绪
阶段三诊断页与薄弱点补漏闭环细化后端 A6 就绪
阶段四适配小程序网页版稳定后

十、待确认事项清单

  1. 题型数量：三种（单选/多选/填空）还是两类？直接决定 QuestionCard 控件与判分逻辑，最优先。
  2. 接口前缀与鉴权：是否有 /api/v1 前缀？是否需要 token？（因登录页暂缓，倾向第一阶段无鉴权）
  3. 答案是否下发：作答阶段 A3 是否返回 answer？建议不下发。
  4. 诊断项是否带 setId：决定"去练习"跳转是否需要前端映射。
  5. 进度回写时机：答完每题即回写，还是整集提交后回写？影响 A5 与完成度计算。
  6. HTTP 库：原生 fetch 还是 axios？建议 axios（拦截器处理错误与 loading 更省心）。

请后端同学重点确认第七章接口清单与数据格式，确认后即可冻结契约、并行开发。
